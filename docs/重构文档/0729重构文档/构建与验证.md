# Coomi Rust 构建与验证

## 工具链

- Rust 1.95.0，由 `codex-rs/rust-toolchain.toml` 固定；
- `rustfmt`、`clippy`、`rust-src`；
- Windows 使用 Visual Studio 2022 MSVC x64 Build Tools；
- Linux 使用上游 Codex 支持的 GNU/Clang 工具链和沙箱依赖。

## 常用命令

在 `codex-rs/` 目录执行：

```powershell
cargo metadata --no-deps --format-version 1
cargo fmt --all -- --check
cargo check -p coomi-provider-adapters -p coomi-cli
cargo test -p coomi-provider-adapters -p coomi-cli
cargo clippy -p coomi-provider-adapters -p coomi-cli --all-targets -- -D warnings
cargo run -p coomi-cli -- --version
cargo run -p coomi-cli -- --help
cargo run -p coomi-cli -- exec --help
```

## Windows rusty_v8 注意事项

当前固定 Codex 依赖中的 `v8 150.4.0` 在 Cargo registry 与 workspace 位于不同盘符时，会尝试在 `target/debug/gn_root` 创建目录符号链接。未启用 Windows Developer Mode 且无 `SeCreateSymbolicLinkPrivilege` 时会报 OS error 1314。

优先方案是为 CI/开发机启用创建符号链接权限，或将 Cargo registry 与 workspace 放在同一盘。临时本地方案是在构建前创建指向准确 registry 源目录的 NTFS directory junction；该路径位于被忽略的 `target/` 中，不得提交，也不得指向未经校验的版本目录。

示例仅适用于当前锁定版本，执行前必须检查源和目标：

```powershell
$v8Source = "$env:USERPROFILE\.cargo\registry\src\index.crates.io-1949cf8c6b5b557f\v8-150.4.0"
$junction = "target\debug\gn_root"
New-Item -ItemType Directory -Force "target\debug" | Out-Null
New-Item -ItemType Junction -Path $junction -Target $v8Source
```

长期 CI 不依赖这个硬编码 registry hash；应使用同盘缓存布局或 Developer Mode。

## 验收纪律

- 先验证固定上游，再验证 Coomi-owned crate；
- 纯上游同步与 Coomi 修改使用不同提交；
- provider 不通过 conformance suite 时保持 disabled/experimental；
- 真实模型 benchmark 必须记录 endpoint、model、effort、权限、仓库 commit 和费用授权；
- 不得用 XML、DSML、正则或自然语言解析补救失败的原生工具调用。
